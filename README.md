# CS305
Final Project-CS305 Cybersecurity

Artemis Financial is a consulting company that builds individualized financial plans for customers, including savings, retirement, investments, and insurance. Their client data and financial information need strong protection because Artemis Financial operates a public web interface for transferring data. Global Rain was asked to address the security weaknesses in the existing software by refactoring the project to add secure communication mechanisms and a file verification step using checksums, so Artemis Financial can meet software security requirements while keeping customer information safe in transit.

When I found security vulnerabilities, I did well by carefully examining the code base for weaknesses and then mapping those issues to concrete remediations rather than making random changes. Coding securely is important because software flaws can lead to data breaches, unauthorized access, tampered data, and loss of customer trust—especially when financial information is involved. Strong software security also adds overall value to a company’s well-being by reducing the risk of regulatory problems, costly incidents, downtime, and reputational damage, while supporting long-term reliability and customer confidence.

The most challenging and helpful part of the vulnerability assessment was translating findings into the correct refactoring actions. The process helped because it made me follow a structured approach (identify issues, address them, and verify fixes) instead of only reacting to errors. This was particularly valuable in CS305 because it connected security concepts to practical code changes and validation steps.

I increased layers of security by adding cryptographic protections and secure transport so data integrity and confidentiality are improved. Specifically, I added a checksum verification step for data integrity, deployed an appropriate cryptographic hash algorithm, and refactored the application to use HTTPS instead of HTTP for secure communications. In the future, I would use additional automated assessment tools (for example, static analysis and dependency auditing) to help prioritize which vulnerabilities to address first and to select the most appropriate mitigation techniques based on risk and impact.

To make sure the application was functional and secure, I ensured the refactored code ran correctly and demonstrated the required security behaviors (checksum verification and browser access over HTTPS). After refactoring, I checked for newly introduced vulnerabilities by running secondary static testing using the dependency-check tool on the code I added and reviewing the output for any reported issues. I also used manual code review as functional testing to look for syntactical, logical, and security problems that automated tools might not catch.

For future assignments, I can reuse the same resources, tools, and habits from this work: secure coding practices (such as using the right cryptographic primitives, avoiding insecure transport, and validating inputs/outputs), following the course’s vulnerability assessment process, and using tools like dependency-check for static testing. I would also keep using structured verification steps—run the app, demonstrate the security requirement in action, and then re-test with security tools—so every change is validated.

For employers, I could show screenshots and documentation from this assignment that demonstrate concrete results: evidence that self-signed certificates were generated, evidence that HTTPS secure communication works in the browser, evidence that checksum verification functions using a unique data string, and evidence that dependency-check ran successfully without introducing new issues. I would also highlight my refactoring work in CS305—what vulnerabilities I identified, what layers of security I added, and how I verified that the system is both functional and more secure.
